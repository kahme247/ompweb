# Spike: omp-web on Bun instead of Next.js

Base: `8e639641` (branch `spike/bun`). Bun 1.4.4, Node v26.8.1, Linux x64.
Every run used `spike/env.sh`: `HOME` and `PI_CODING_AGENT_DIR` point at `/tmp/bunspike/home` (one copied fixture session) and `OMP_WEB_OMP_BIN=/nonexistent/omp`, so no real `~/.omp` and no real `omp` was touched.
Extra packages (`bun-plugin-tailwind@0.1.2`) were installed into `/tmp/bunspike/deps`, not into `node_modules`.

**Overall result: no hard blocker.** All 70 API route modules, the SSE stream, the daemon link, the password gate, `node:sqlite`, `sharp`, `web-push` and the React app run on Bun. The work is replacing what Next did implicitly: the router, the HTML shell, fonts, static serving, the launcher and service scripts. A compiled single binary also works, but `sharp`, the self-update path and the service scripts need separate work.

### Front end: errors by category (probe 9)

1. **`next/dynamic`** (3 files, 9 call sites: `AppShell`, `CommandPaletteMount`, `SettingsConfig`). The build compiles, but Next's client internals fail at runtime. Fixed with a 19-line `React.lazy` + `Suspense` shim (`spike/shims/dynamic.tsx`); every Settings tab loaded.
2. **`next/navigation`** (1 file: `AppShell`, `useRouter().replace` ×8 + `useSearchParams`). Without a shim the page fails with `ReferenceError: process is not defined` (`process.env.__NEXT_CACHE_COMPONENTS`), then `invariant expected app router to be mounted`, and renders nothing. Fixed with a 27-line `history` + `useSyncExternalStore` shim (`spike/shims/navigation.tsx`). With both shims the `window.process` stub is no longer needed.
3. **`next/font/google`** (`app/layout.tsx`: Geist, JetBrains Mono, Noto Sans Mono, Source Serif 4). This only works inside Next. The SPA renders with `--font-geist`, `--font-jb-mono`, `--font-noto-mono` and `--font-source-serif` empty, so text falls back to default fonts. Fix: self-host the woff2 files with `@font-face` in `globals.css`.
4. **Server-only Next APIs** (`next/headers`, `next/script`, `Metadata`/`Viewport` in `app/layout.tsx` and `app/page.tsx`). Replaced by a static `spike/index.html`. Still to carry over: the theme, language and font-size inline scripts (only theme is ported), `SIDEBAR_HISTORY_BRIDGE_SCRIPT` before React, the install name in `<title>` (`getInstallName(headers)`, which the server must inject into the HTML; the spike hard-codes "omp web"), and the `/login` page.
5. **CSS.** Tailwind 4 through `bun-plugin-tailwind` compiles `app/globals.css` (4634 lines; `@source`, `@theme`, `@font-face`) without errors, and the computed styles are right. Two build errors were fixed by config: `<link rel="manifest" href="/api/manifest">` gives `Could not resolve` (the bundler tries to bundle it; add the link outside the bundler), and `Multiple files share the same output path` (KaTeX CSS) is fixed by `naming: "[name]-[hash]"`. Still open: the KaTeX CSS from `lib/markdown.ts`'s dynamic import is merged into the entry CSS, with all 60 KaTeX fonts inlined as base64 (ttf/woff/woff2), and is emitted twice.
6. **Other.** `NEXT_PUBLIC_*` (3 vars) needs `define`. 6 duplicate-key warnings in `lib/i18n/locales/{en,ja,zh-CN}.json` (`agentsConfig.scopeUser/scopeProject`) are an existing data bug that Bun reports. `public/event-stream-worker.js` needs its content-hash URL (done today in `next.config.ts`). `@types/bun` is missing, so the LSP flags `Bun`/`import.meta.dir`.

## Blocking risks

No hard blocker found. Ranked risks:

1. **Distribution.** Today users need only Node. On Bun they need Bun installed (`bun add -g`), or we ship 115–125 MB binaries per platform. The binary path breaks `sharp` (the native addon cannot be embedded), npm-based self-update, and every service script.
2. **Silent behavior loss when Next goes away.**
   - Bun's 10 s default `idleTimeout` kills SSE and the daemon link unless it is disabled.
   - `undici` resolves to a Bun stub, so the dispatcher is a quiet no-op.
   - `fs.accessSync` returns `null`, which breaks the systemd/tray executable checks.
   - Static asset caching/compression, the middleware matcher and body cap, `x-middleware-*` headers, fonts and the worker URL hash must all be rebuilt by hand.
   - Each of these failed silently, not with an error.
3. **Windows is unverified.** Nothing ran on Windows. The PowerShell supervisors and `windows-service.ts` hard-code `node.exe`, `.next` and `next dev`, and Bun on Windows under Task Scheduler and the tray was not exercised.
4. **Tests.** `bun run` cannot execute `node:test` files at all. `bun test` needs infrastructure changes (37 failures, 258 when run in one process). Two runtimes (Node for tests, Bun for the app) remain an option.
